# 中断与恢复

此文件说明 Buddy Creator Skill 1.3.0 的 Python 项目恢复范围；不使用旧版 sessionId、workToken、LangGraph 检查点或 Node 启动器。

| 情况 | 处理方式 |
| --- | --- |
| 同一条输入的提交响应丢失 | 用原 clientKey 和原 raw 重试 turn_begin；同一身份不能换原话 |
| 已保存输入，宿主撰写中断 | 用 turn_continue 读取已有工作和 context，继续同一 turnId，不重新输入旧答案 |
| turn_finish 返回具体校验错误 | 修正本轮 patch 或 delivery 后重新提交；保留原输入与已保存来源，不创造确认 |
| 不清楚 finish 是否成功 | 先 turn_continue 或 status 查看实际回执；已成功回合不能换正文重放 |
| 用户明确暂停 | 保存 paused；停止提问，已保存内容可在下一次 open 恢复 |
| 纯答疑 | 保存用户问题和解释，保留原待答对象；解释不算采访回答，不借机推进 |
| 用户修订已有内容 | 只改受影响对象；保留旧版本和原话，原确认及依赖受影响时重新校准 |
| 资料只取得片段 | 保存 partial 和真实缺口，不把来源标为完整可用；补齐后用新 operationId 导入 |
| 用户换宿主继续 | 使用同一个 workspace；先 open，再读取保存的 delivery、原话和目标。保留 gapId、缺口次数、无新增记录及目标总次数，不重置 |
| 已收口后主动补充 | 用有本轮原话依据的 interview.resolutions 解决具体缺口并修订；只有明确针对该目标的续谈要求才用 interview.reopen |
| 所有独立目标均无法推进 | 保存具体缺口及恢复条件，使用 delivery.blocked；不能假装用户暂停或重新盘问耗尽的细节 |
| 四册已确认但成果文件生成失败 | 保留确认，处理具体错误后调用 finalize |

重试只恢复实际保存的操作；本地程序无法恢复宿主从未发送的消息、从未提交的标注意见或外部工具内部进度。不要声称仍有未实际启动的后台任务。

## 预览连接

同一项目保存固定的本机预览入口。再次 open 优先复用原入口并启动缺失的预览进程，不能为了恢复随意删掉端口与身份记录。页面只监听本机 127.0.0.1，内容与事件接口只读。页面已加载时可重试读取更新；预览进程退出时，需要宿主重新 open 启动后刷新原地址，浏览器本身不能重启程序。

若固定端口被其他进程占用，说明真实冲突，不停止身份未知的程序，也不承诺旧 URL 会自动跳到新端口。具体错误依据返回值处理。预览只负责显示已保存进度和公开草稿，不能修改内容或代替用户确认。本轮登记为 working 后 120 秒没有新的实际更新，页面显示“本轮还未完成”，避免无限播放像是在持续思考的动画；这不代表原输入丢失。

## 工作目录与历史

新项目从空白开始；此前 Python 无 Node 试用版项目可通过 `open --workspace` 原路径接续，保留原话、产物和确认，也保留预览端口与身份。原 Python 预览进程仍可用时可复用，不需要为升级搬动项目。新建默认使用当前创作目录下的 buddies/；同一 creation-key 已在原 buddies-no-node/ 匹配到项目时复用该目录，不重复创建。

本版本不自动迁移旧 Node 0.x 工作目录或其 SQLite/LangGraph 检查点；需要参考旧作品时只导入创作者选择的资料，不改写原项目。所有新内容由 Python 工具写入本项目的 state.json 与归档、历史、成果目录。宿主不能直接修改 state.json 绕过版本、证据或确认校验。

本版本没有旧版 interviewCycleId 重置接口。用户大幅改变定位、人群或核心任务时，先保留原话、评估受影响内容；若需要重做整个访谈，基于用户明确改向另开独立项目，保留原项目，不以重建项目规避暂停、责任边界或确认。

1.0.0 与 Python 试用项目仍可读取；只 open 不改写状态。首次新提交以历史真实回答初始化缺口记录，原有关闭状态和确认继续保留。仍在等待回答的旧问题不需要重新问，按当前 host-guide 提交 assessment。

完整操作字段见 [宿主调用协议](host-guide.md)。
